# Contributing

`drop-ads` welcomes privacy-preserving community testing, filter-list submissions, bug reports, documentation improvements, and code contributions.

## Code contributions

Before opening a pull request, read `CONTRIBUTOR_TERMS.md`. By intentionally submitting a pull request for inclusion, you agree that its contribution is offered under those terms. This preserves the copyright holder's ability to relicense the project later.

Keep changes privacy-preserving. Do not add analytics, telemetry, browsing/request history, user identifiers, advertising identifiers, or a custom tracking backend.

## Filter-list contributions

Community block candidates use the GitHub issue workflow described in `docs/COMMUNITY.md`. The extension can prepare a privacy-minimal issue containing only the normalized candidate domain. Manual submissions should use the Community block issue template.

A submitted candidate is not production policy until automated validation passes, a maintainer approves it, and the resulting promotion pull request is reviewed and merged.

## Bug reports and testing feedback

Please report reproducible browser/version details, what you expected, and what happened. Screenshots are welcome when they do not expose private information.

## Security and privacy issues

Do not put private browsing data, tokens, cookies, credentials, account identifiers, or sensitive URLs in an issue. Reduce examples to the minimum needed to reproduce a problem.
